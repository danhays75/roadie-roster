# Project Guidance

## User Preferences

- Red, white and blue look: navy #14284B header, red #B22234 primary buttons and accents, blue #2B5DA8 for hired/done, warm white #F5F3EE page, white cards
- Oswald uppercase headings, Inter body text, thin red-and-white stripe under the header
- Touch targets at least 44px
- Fully responsive and installable as a PWA
- Store logo appears in the header, on roadie cards and as the app icon
- Match the attached reference card image for the roadie card's visual styling
- Leader cards reuse the roadie card component and roadieCard.css with tier ribbons and gold, platinum and legend variants
- Leader About Me fields use the same labels, placeholders, Spanish copy and 200-character caps as the kiosk
- Leaders never count toward on-hand or build-to and never appear in the position roster
- No contact information on any card or gift bag label
- Do not touch tests and change nothing else
- Uniform defaults, size curve and buffer are Admin/Store Manager editable; the Uniforms page is viewable by Admin, Store Manager and Training Manager
- Roadie shirt and hat sizes are not contact information and are visible to leaders
- Keep demo-mode partitioning and the requireReal* guards on every new uniform write
- Do not touch tests and change nothing outside the uniforms batch
- The roadie card front badge is always the drawn scalloped StoreSeal with the store number; never a logo badge
- The card back has no ROADIE STATS section and no Favorite movie row; the back order is Hometown, Crew, Day off, Favorite team, Favorite candy, Favorite drink, Favorite color, Fun fact, Hired, then MY GOAL
- The card front keeps the MINOR tag but never a birthday tag
- Position uniforms use one field set: shirtType, shirtQty, hatType, hatQty
- Never change app behavior to satisfy outdated tests

## Learnings

- archiveReasonLabel in src/frontend/src/components/roadie/RoadieTile.tsx is shared by the roadie tile and PositionRosterDialog's ArchivedRow; it maps ncnsOrientation and paperworkIncomplete.
- The inherited frontend suite has pre-existing failing tests that predate this draft; the tester owns src/frontend/src/__tests__/ and test/pocketic/.
- Orientation check-off writes are split: saveUniformCheckoff(roadieId, uniformItems, uniformCounts) writes only uniform fields and setPaperworkItems(roadieId, paperworkItems) writes only paperworkItems, so neither clobbers the other; both create the record with the active isDemo when missing.
- Auth.requireOrientationStaff (admin, storeManager, trainingManager, visitingManager) guards getOrientationSessionView, markPresent, getUniformCheckoff and saveUniformCheckoff; undoPresent, moveRoadieToSession, archiveNoShows, rehire and the paperwork override stay Admin/Store Manager only.
- markPresent(roadieId, eventId, overrideReason : ?Text) traps 'Paperwork incomplete' unless an Admin or Store Manager supplies a non-empty reason, which is logged as 'Marked present with paperwork override: <reason>', and rejects archived roadies with 'Roadie is archived; rehire first'.
- Orientation.tsx separates canPresent (canOrientation, includes trainingManager/visitingManager) from canManage (canArchive, Admin/Store Manager only) so the Present button is enabled for orientation staff while archive/move/undo/override stay manager-only.
- Roster.tsx defaults to an All tab (Pending + Active together) and passes rosterStateLabel to RoadieTile only on the All tab; the CardList type includes 'all'.
- ManagerTab.tsx wires the paperwork checkboxes to setPaperworkItems with applicable-item filtering, a 'Paperwork n of m' count and a Complete badge; useSetPaperworkItems invalidates roster, orientation session and alerts.
- Orientation session assignment: listOrientationSessions() returns #orientation events ordered by start; listUnassignedPendingRoadies() returns pending roadies whose orientationEventId is null or dangling; moveAllRoadiesToSession(fromEventId, toEventId) moves every non-archived roadie between sessions and logs the count; moveRoadieToSession(roadieId, eventId) stays the single-roadie change.
- UnassignedSection assigns each unassigned roadie through the per-roadie moveRoadieToSession, not the bulk move, because the bulk move only relocates roadies already attached to a source session.
- SchedulePanel gates Move everyone on ARCHIVE_ROLES (admin/storeManager) and event.kind === orientation, matching the backend requireManager guard on moveAllRoadiesToSession.
- Migration src/backend/migrations/00000013_000000.mo reassigns only rosterState == #pending roadies whose orientationEventId is null or names a missing/non-orientation event to the earliest upcoming orientation session, leaving all others untouched.
- Map.map on a Map<Nat, Roadie> returning Roadie needs explicit <Nat, Roadie, Roadie> when the lambda's branches do not let inference pick V2 (M0098).
- pnpm fix (biome --write) reformats test files under src/__tests__; revert them with git checkout after running it so the tester-owned tests stay untouched.
- Uniform order rows are grouped by the backend item label (Polo/Cap) via groupOrderRows; the Uniforms page renders one table per group.
- getUniformOrder filters r.isDemo == Auth.demoActive(demoState), so demo and real uniform counts never mix.
- Position uniform defaults (shirtType/shirtQty/hatType/hatQty) round-trip through TemplatePosition in both download and load.
- Roadie shirt/hat sizes live in profile, not the contact set, so redact() leaves them visible to read-capable roles.
- FlipCard's bottle-cap badge aria-label is the static t('roadie.card.badge') copy, not the async store number; the front badge order is secondary logo, then main logo, then the drawn StoreSeal.
- FlipCard's front badge is always the drawn StoreSeal with the store number; StoreBadge, StatBar, the ROADIE STATS section and the birthday tag were removed, and roadieCard.css dropped .tag.birthday/.stats/.h/.stat/.bar while keeping .cap/.cap .seal.
- The card back table order is Hometown, Crew, Day off, Favorite team, Favorite snack, Favorite drink, Favorite color, Fun fact, Shirt size, Hat size, Hired, then MY GOAL.
- Position and TemplatePosition carry only shirtType, shirtQty, hatType, hatQty; migration 00000015 folds defaultShirts/defaultHats into shirtQty/hatQty only where the surviving qty is 0, then drops the legacy pair.
- getUniformOrder builds rows from the cartesian product of in-scope item labels and curve/real sizes, so a house filter with zero hired roadies still returns every item/size row with hired 0.
- getUniformOrder projectedCount sums (unfilled + missingSize) * qty across in-scope positions, then applies the curve once with (units * percent + 50) / 100; withBuffer rounds up per row; UniformOrderView.totals is one row per item (item/hired/projected/orderTotal).
- defaultCount in phase23.mo matches a count item's text containing 'shirt' or 'hat' to pre-fill from the position's shirtQty/hatQty.
