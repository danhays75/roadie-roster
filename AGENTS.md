# Project Guidance

## User Preferences

- Red, white and blue look: navy #14284B header, red #B22234 primary buttons and accents, blue #2B5DA8 for hired/done, warm white #F5F3EE page, white cards
- Oswald uppercase headings, Inter body text, thin red-and-white stripe under the header
- Touch targets at least 44px
- Fully responsive and installable as a PWA
- Store logo appears in the header, on roadie cards and as the app icon
- Match the attached reference card image for the roadie card's visual styling
- Leader cards reuse the roadie card component and roadieCard.css with tier ribbons and gold, platinum and legend variants
- Leader About Me fields use the same labels, placeholders, Spanish copy and 200-character caps as the kiosk
- Leaders never count toward on-hand or build-to and never appear in the position roster
- No contact information on any card or gift bag label

## Accepted Requirements

- Photos and signatures upload to real storage and are role-gated (Admin/Store Manager for signatures)
- submitSignup requires Kiosk, Store Manager or Admin and caps text field lengths
- The roadie's drawn signature is kept in the contact set; the manager's approval signature is stored separately and drawn on-device
- Multi-stroke signatures survive resize and rotation
- Real age in store time blocks under-minimum-age positions; isMinor and birthdayMonthDay are exposed without date of birth
- Sign out in the header, waiting/error gates and a PIN-protected kiosk spot
- Kiosk auto-reset after 10 seconds and on 90 seconds idle; kiosk renders without app header/nav; no listPendingUsers for non-admins
- Store Manager sees approvals; only admins see pending users; suggested orientation is saved; reject asks for confirmation
- Date-only displays use UTC; schedule times use store time zone
- Access end dates build 11:59:59 PM America/Chicago; admins can change end dates and trainer stations after approval
- On-hand counts each roadie once under their main position only
- updateRoadieStatus cannot archive; archive requires a reason and rehire requires a non-blank reason
- Trainer with no stations sees no roadies; Integration sees only the Shareable export
- Last admin cannot be demoted, overwritten or end-dated; approveUser only for pending principals
- Full export runs only on Download tap and includes the whole contact set; totals rows show Total Par and Need
- Route guards block pages a role cannot use and hide Edit/Change Position
- Waiting screen polls getMyAccess; bootstrapAdmin only when no admin exists; ensureSeeded only for Admin
- RoadieCard validates the id before BigInt and has an error boundary
- Service worker caches only the app shell and hashed assets, skips non-OK responses, and versions the cache per build
- PWA has 192 and 512 icons (one non-transparent maskable), apple-touch-icon and iOS meta tags
- The header title text is "Roadie Roster"
- The browser tab title, PWA manifest name and short_name, and apple-mobile-web-app-title are "Roadie Roster"
- The store name and location stay as the subtitle
- Store info carries an optional secondary logo defaulting to null
- The public logo query returns both logos for the kiosk and sign-in screens
- Admin > Store info has a Secondary logo upload with preview and Remove, reusing the main logo's resize/compress helper and image-type detection
- The secondary logo replaces the star badge next to the store name in the header and dashboard banner, at the same height as the main logo, with nothing shown when absent
- The main logo stays exactly as it is now
- Both logos refresh after Save without a page reload
- Fix the blank Card tab so the roadie card renders between the tabs and the Flip card button
- Restyle the roadie card as a collectible trading card with a holographic foil shell and a 3D flip
- Card text at least 14px, no sideways scrolling, and no phone, email or date of birth on the card
- Change nothing outside the card component
- Self-host Archivo Black and Oswald so the card's display fonts load reliably
- Replace the card-front badge with the inline SVG store seal showing the store number

- Add a hireDate to the Roadie record, set it from the sign-up's submission time on approval, and fall back for existing roadies

- Remove the ROADIE STATS section and list every non-empty About Me field in the back table
- Keep the MY GOAL quote under the back table

- Opening and after-opening build-to are editable number inputs (inputMode numeric, min 0, max 999, integers only) that keep the minus and plus buttons and save on blur or Enter

- A 'Tell us who you are' form appears after a new Internet Identity sign-in and before the waiting screen, storing the profile on the pending request and carrying it onto the access grant

## Learnings

- Crew ids start at 0n (nextCrewId counter), so 0n is a valid crew id and cannot be the add-vs-edit sentinel; use an explicit null id. createCrew(name) cannot set a leader, so persist a chosen leader by chaining createCrew then updateCrew(newId, name, leader).
- The Crews tab lives in src/frontend/src/components/admin/CrewsPanel.tsx and is registered in src/frontend/src/pages/Admin.tsx, gated to Admin and Store Manager; hooks/useQueries.ts has useCreateCrew/useUpdateCrew/useDeleteCrew.
- findDuplicates in lib/signup.mo matches phone OR email, includes archived roadies, and populates name, mainPositionName and matchedOn; matchedOn reports 'phone' when the phone matches and 'email' only when the email is the sole match. DuplicateMatch = { roadieId; name; mainPositionName; matchedOn; archived } in types/signup.mo.
- The Approve sign-up screen is src/frontend/src/pages/Approvals.tsx; PendingSignupCard pre-selects the crew led by the approving user via an effect keyed on loaded crews plus a touched flag, and DuplicateList renders the matched roadie's name, main position, match type and archived state as a link to /roster/$roadieId.
- RoadieTile (src/frontend/src/components/roadie/RoadieTile.tsx) is the shared roadie tile: photo via useRoadiePhoto(roadie.id) + memoized refToDataUrl, 4:3 object-cover top, navy-on-cream initials fallback, name, status badge, crew tag, MINOR tag, and a grayscale archived variant.
- RoadieCardModal (src/frontend/src/components/roadie/RoadieCardModal.tsx) is the shared card pop-up: Radix Dialog with FlipCard at 420px max, flip, X/outside/Esc/back-button close via a pushed history entry, swipe/arrow/prev-next navigation, an N of M counter, neighbor photo preload, and a manager-only full-profile link.
- RoadieCardModal.close() must call the close callback directly after history.back(); the popstate handler only fires for genuine back-button navigations (pushed.current still true), so relying on popstate alone leaves X/Esc/tap-outside unable to close the modal.
- The position roster dialog's Present-mode banner renders StoreLogo (data-ocid=store.logo); the modal's FlipCard uses StoreSeal, so the banner is the dialog's only store mark.
- The position roster dialog and Roster page both have a Show former (n) toggle revealing archived roadies in a separate No longer a roadie section with grayscale tiles and the archive reason; archived roadies never count toward on-hand.
- The inherited suite has 22 pre-existing failing tests that predate this draft and remain failing; the Leaders page test that expected a direct anchor link to /leaders/<principal> was updated for the new tile-opens-pop-up behavior.
- Demo mode lives in src/backend/lib/demo.mo with the firewall helpers; main.mo includes DemoApi and exposes getDemoState, setDemoMode, setDemoRole, setPretendDate, getDemoDataSummary, loadDemoData and clearDemoData.
- Demo records are marked with isDemo on Roadie, Crew, ChangeLogEntry, SignupSubmission, AttendanceRecord and TrainerNote; every read, list, count and export filters isDemo == Auth.demoActive(demoState).
- Demo leaders are marked by staffProfile.workEmail == ?"DEMO"; Auth.isDemoLeader centralizes that marker and both listLeaders and getGiftBags gate on isDemoLeader(g) == demoActive(demoState).
- The demo auto-off is armed with Timer.setTimer<system> in mixins/demo-api.mo scheduleAutoOff and logged with systemActor(), so the automatic off is recorded even with no later update.
- The frontend demo banner is src/frontend/src/components/DemoBanner.tsx; DemoBannerHost must render its own DemoBanner outside the DemoBannerHosted provider or the bar is hidden on every screen.
- The admin demo switch is src/frontend/src/components/admin/DemoModePanel.tsx rendered by components/admin/StoreInfoPanel.tsx; the Sign as Test button is in components/kiosk/KioskSignatureStep.tsx and components/approvals/ManagerSignaturePad.tsx.
- pretendDateToInstant in src/frontend/src/lib/format.ts maps a PretendDate (UTC day + AM/PM) to a JS Date; OpeningTimeline's useNow and Kiosk's effectiveNow consume it while demo mode is on.
- The inherited suite has 22 pre-existing failing tests that predate this draft and remain failing; the demo mode work added passing tests without changing them.
- The per-caller demo role lives in demoState.demoRoles : Map<Principal, DemoRoleEntry> in src/backend/types/common.mo, with migration src/backend/migrations/00000011_000000.mo dropping the old global demoRole/demoTrainerStations; Auth.demoRoleFor defaults a signed-in caller with no entry to #admin and returns null for anonymous.
- Auth.requireRealSettingsAdmin/requireRealSettingsManager call requireRealAdmin/Manager first, then trap 'Turn off demo mode to change real settings' while demoActive; they guard approveUser, updateUserRole, removeUser, updateAccessEnd, updateTrainerStations, setKioskPin, updateStoreInfo, position/schedule/checklist/retention writes, adjustBuildTo and the store template writes, while reads keep requireReadable.
- getMyAccess returns MyAccessView { grant : ?AccessGrant; demoRole : ?DemoRole }; hooks/useAccess.ts normalizeAccessView tolerates a bare AccessGrant so inherited mocks keep passing.
- listAccessGrants filters isDemoLeader(g) == demoActive(demoState) and listPendingUsers returns [] while demo is on, so real grants and pending requests never leak.
- Admin.tsx hides the real-settings tabs while demo is on but keeps the Store tab so an Admin can reach the demo switch; activeTab falls back to store if a hidden tab was selected. Panels that self-gate on demo.enabled must place the early return after every hook.
- Four committed PocketIC tests (test/pocketic/backend-demo.test.ts, test/pocketic/backend-template-and-profile.test.ts, test/pocketic/backend.test.ts) still assert the old global demo role and old getMyAccess tuple shape; they are stale and need updating to the per-caller DemoStateView.demoRole and MyAccessView shapes.
- The inherited frontend suite has 22 pre-existing failing tests that predate this draft and remain failing; the backend PocketIC lane passes.
